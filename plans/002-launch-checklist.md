# 계획 002: 출시 전에 반드시 되돌려야 할 것들을 저장소 안 한 파일로 모은다

> **실행자 안내**: 이 계획은 **코드 동작을 하나도 바꾸지 않는다.** 문서 하나를 만들고,
> 흩어져 있는 표시들이 그 문서를 가리키게 하는 일이다. 각 단계의 확인 명령을 돌리고
> 기대 결과를 본 뒤 다음으로 넘어가라. 끝나면 `plans/README.md` 상태 칸을 고쳐라.
>
> **어긋남 확인 (제일 먼저)**: `git diff --stat a99c979..HEAD -- lib/copy.ts app/robots.ts lib/weather.ts app/layout.tsx app/page.tsx`
> 결과가 비어 있지 않으면 아래 "지금 상태" 의 줄 번호와 실제 코드를 대조하고,
> 다르면 멈춰야 할 때로 취급하라.

## 상태

- **우선순위**: P1
- **품**: 작음(S)
- **위험**: 낮음 (코드 동작 변경 없음)
- **선행**: 없음
- **분류**: docs
- **작성 시점**: 커밋 `a99c979`, 2026-08-18

## 왜 중요한가

이 사이트는 **일부러 손님에게 안 보이는 상태**로 만들어져 있다. 검색을 막아뒀고, 화면 글은 한국어로 띄워뒀고,
사진은 임시로 넣었고, AI 는 무료 등급을 쓰고 있다. 하나하나가 의도된 선택이고, **손님을 받기 전에 전부 되돌려야 한다.**

문제는 그 목록이 **어디에도 한곳에 없다는 것**이다. 지금은 코드 곳곳의 주석과 사람의 기억에 흩어져 있다.
여섯 개 중 하나만 빠뜨려도 결과가 크다 — 예를 들어 `LANG` 을 안 되돌리면 **해외 손님 전원이 한국어 화면을 본다.**

이 계획은 그 목록을 저장소 안에 만들어, `git pull` 하는 사람이면 누구나(그리고 어느 AI 든) 보게 만든다.

## 지금 상태

되돌려야 할 것이 실제로 어디 있는지 — **전부 직접 확인한 위치다.**

| # | 파일 | 지금 | 출시 때 |
|---|---|---|---|
| 1 | `lib/copy.ts:15` | `export const LANG: "ko" \| "en" = "ko";` | `"en"` 으로 |
| 2 | `app/robots.ts` | 파일 전체가 `Disallow: /` | **파일 삭제** |
| 3 | `app/layout.tsx` | `robots: { index: false, follow: false }` | 두 줄 삭제 |
| 4 | `app/page.tsx` | `public/seoul-blue-hour.jpg` (AI 생성 그림) | 실제 사진으로 교체 |
| 5 | `lib/weather.ts` | Open-Meteo (무료 등급 = **비상업용**) | 기상청 API 로 |
| 6 | `app/privacy/page.tsx:13` | `const CONTACT = "hello@example.com"` | 진짜 주소로 |

코드 밖에 있는 것도 둘 있다 — 파일에 표시가 없으니 **문서에만 적힌다**:

- **Gemini 를 유료 등급으로 올리기** — 지금 무료 등급은 제출 내용을 모델 개선에 쓰고 사람이 볼 수 있다.
  여행 폼의 식이·접근성 칸에 종교(할랄)나 건강(알레르기·휠체어) 정보가 들어온다
- **사업자 정보** — 처리방침 8장에 상호·대표자·등록번호·주소가 비어 있다

이미 코드에 달려 있는 표시 (형식을 맞출 때 참고):

- `app/page.tsx` 의 사진 위 `TODO(출시 전):` 주석 블록
- `lib/copy.ts` 맨 위 주석 — `**손님을 받기 전에 아래 값을 "en" 으로 되돌린다.**`
- `lib/weather.ts` 맨 위 주석 — `⚠️ 출시 전에 갈아타야 한다`

### 이 저장소의 규칙

- 문서는 **한국어**로 쓴다. 두 사람 다 개발 입문자다 (`AGENTS.md` 0장)
- 전문 용어는 처음 나올 때 괄호로 뜻을 푼다
- 표를 즐겨 쓴다. `AGENTS.md` 가 좋은 예다
- 규칙 문서의 원본은 `AGENTS.md` 하나다. **이번 계획은 `AGENTS.md` 를 고치지 않는다** (뮤조 담당 파일이고, 공용 파일이라 미리 말해야 한다)

## 범위

**만들거나 고쳐도 되는 파일**:
- `LAUNCH.md` (새로 만듦, 저장소 루트)
- `lib/copy.ts` — 주석 한 줄만 추가
- `app/robots.ts` — 주석 한 줄만 추가
- `lib/weather.ts` — 주석 한 줄만 추가

**건드리면 안 되는 것**:
- **어떤 코드의 동작도 바꾸지 않는다.** `LANG` 값을 `"en"` 으로 바꾸지 말 것 — 아직 출시가 아니다
- `app/robots.ts` 를 삭제하지 말 것 — 지금은 막혀 있어야 한다
- `AGENTS.md` — 공용 규칙 파일. 뮤조와 상의 없이 안 고친다
- `README.md` — 세팅 안내용이다. 출시 목록은 별도 파일로 둔다

## 단계

### 1단계: `LAUNCH.md` 를 만든다

저장소 루트에 만든다. 아래를 **모두** 담아야 한다:

1. 맨 위에 한 줄 경고 — 이 목록을 다 끝내기 전에는 손님·광고·SNS 에 주소를 뿌리지 않는다
2. 위 "지금 상태" 표의 6개 항목. 각 줄에 **파일 경로와 무엇을 어떻게 바꾸는지**를 적는다
3. 코드 밖 항목 2개 (Gemini 유료 전환, 사업자 정보)
4. **순서 주의** 한 줄: `Gemini 를 유료로 올리기 전에 입력 길이 상한(plans/001)이 먼저 들어가야 한다`
5. 각 항목 앞에 `- [ ]` 체크박스를 둔다
6. 각 항목에 **왜 그렇게 해뒀는지**를 한 줄씩 적는다. 이유를 모르면 나중에 누군가 되돌린다

**확인**: `test -f LAUNCH.md && grep -c "\- \[ \]" LAUNCH.md` → 8 이상

### 2단계: 코드에 있는 표시가 이 문서를 가리키게 한다

아래 세 파일의 **기존 주석에 한 줄씩만** 덧붙인다. 주석 내용을 지우거나 코드를 고치지 않는다.

- `lib/copy.ts` — `LANG` 위 주석 끝에: `전체 목록은 저장소 루트 LAUNCH.md 참고.`
- `app/robots.ts` — 파일 맨 위 주석에 같은 문장
- `lib/weather.ts` — 맨 위 주석의 `⚠️ 출시 전에 갈아타야 한다` 아래에 같은 문장

**확인**: `grep -rln "LAUNCH.md" lib/ app/` → 3개 파일

### 3단계: 아무것도 안 깨졌는지 본다

**확인**: `npm run build` → `✓ Compiled successfully`
