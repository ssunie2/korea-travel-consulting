# 배포 화면 확인 — 작업 순서와 완료 기준

> **PR 을 리뷰하거나 머지한 뒤, 화면이 실제로 도는지 확인하는 절차다.**
> 이 저장소에서 같은 확인을 매번 새로 짜고 있었다. 실제 사고를 세 번 잡았고(→ `notes.md`), 그 셋이 전부 **"랜딩만 보면 멀쩡해 보이는"** 종류였다.

## 1. 언제 쓰나

- **PR 리뷰할 때** — 특히 화면·문구·CSS 변경
- **머지한 뒤** — 본 배포가 깨지지 않았는지
- **"사이트 이상한데?" 소리를 들었을 때** — 원인이 코드인지 DB 인지 인프라인지 가른다
- **인프라를 건드린 뒤** — 이전, 환경변수 변경, 플랜 전환

한 줄 문구 수정처럼 되돌리기 쉬운 변경에 전부를 돌릴 필요는 없다. **DB·환경변수·CSS·배포 설정을 건드렸다면 돌린다.**

## 2. 입력과 출력

| | |
|---|---|
| **입력** | 확인할 주소 하나. 본 배포이거나, PR 에 Vercel 봇이 달아둔 미리보기 주소 |
| **출력** | 통과/실패 목록 + 실패 시 원인 후보. PR 리뷰라면 **본 배포와 나란히 둔 대조표** |

미리보기 주소는 PR 페이지의 Vercel 봇 코멘트에 있다. **2026-09-18 이후 로그인 없이 열린다**(이슈 #68).

## 3. 역할

- **누구든** 이 검사를 돌릴 수 있다. 읽기만 하므로 사이트에 영향이 없다
- **리뷰하는 쪽**이 돌린다. 규칙 3장 2번 — 리뷰가 끝난 쪽이 머지한다
- 실패가 인프라(잠든 DB, 보호 설정, 환경변수) 때문이면 **Vercel 대시보드를 가진 뮤조**가 처리한다

## 4. 작업 순서

### ① 주소가 도는지

```bash
bash docs/playbooks/preview-check/files/check-urls.sh
```

미리보기를 보려면 주소를 붙인다.

```bash
bash docs/playbooks/preview-check/files/check-urls.sh https://<미리보기-주소>.vercel.app
```

랜딩·폼·FAQ·문의·개인정보(200), 관리자(401), **그리고 DB 를 읽는 샘플 초안 4개**(200)를 검사한다.
샘플 초안 아이디는 `app/page.tsx` 에서 그때그때 뽑으므로 아이디가 바뀌어도 따라간다.

### ② 화면이 의도대로 바뀌었는지 (CSS·크기·간격을 건드린 PR만)

**PR 설명을 믿지 않는다.** 같은 폭에서 본 배포와 브랜치를 각각 재서 대조한다.

1. 미리보기 주소를 연다
2. 폭을 맞춘다 — **PC 1440 / 폰 375**
3. `files/measure.js` 의 `measure()` 를 실행한다
4. 본 배포에서 **같은 폭·같은 선택자로** 다시 잰다
5. 표로 나란히 놓는다

### ③ 폼이 실제로 보내지는지 (폼을 건드린 PR만)

⚠️ **미리보기는 본 배포와 같은 환경변수를 쓴다 = 진짜 DB 에 들어간다.**
서버에 `delete` 권한이 없어서(설계상 의도) 시험 줄은 대시보드에서 지워야 한다.

**그래서 기본은 보내지 않는다.** 화면 표시와 입력 검증까지만 확인하고, **전송은 "미확인"으로 구분해 보고한다.** 꼭 보내야 하면 지울 사람과 미리 합의한다.

## 5. 판단 규칙

| 무엇을 건드렸나 | ① | ② | ③ |
|---|---|---|---|
| 문구만 | ✅ | — | — |
| CSS·크기·간격·반응형 | ✅ | ✅ | — |
| 폼·서버 액션 | ✅ | — | ✅ |
| DB·마이그레이션·환경변수 | ✅ | — | 합의 후 |
| 인프라(이전·플랜·보호 설정) | ✅ | — | — |

## 6. 완료 기준

각 항목을 **통과 / 실패 / 미확인 / 해당 없음** 으로 적는다.

| 확인할 것 | 근거 |
|---|---|
| 주소가 산다 | `check-urls.sh` 출력 전문과 종료코드 |
| 크기·간격이 의도대로다 | 같은 폭에서 잰 **본 배포 vs 브랜치** 수치 대조표 |
| 폼이 들어간다 | 실제 전송 결과. 안 했으면 **미확인**으로 적고 이유를 남긴다 |

**"좋아 보인다" · "코드를 읽어봤다" 를 확인했다고 적지 않는다.** 지난 배포가 통과했다는 사실은 이번 변경의 근거가 아니다.

## 7. 재사용 자료

| 파일 | 언제 |
|---|---|
| `files/check-urls.sh` | 항상 (①) |
| `files/measure.js` | 화면 크기·간격을 건드린 PR (②) |
| `notes.md` | 실패했을 때 — 같은 증상이 있었는지 먼저 본다 |

프로젝트 검사(`npm test` · `npm run lint` · `npx tsc --noEmit`)는 원래 자리에 있다. **이 절차는 그것들을 대신하지 않는다** — 배포된 화면을 보는 부분만 맡는다.

## 8. 알려진 예외

- **랜딩만 200 이고 초안만 404** → Supabase 가 잠들었다. 코드 문제가 아니다 (이슈 #71)
- **302 로 `vercel.com/sso-api`** → 미리보기 보호가 켜져 있다 (이슈 #68)
- **랜딩 정거장 구간 캡처가 빈 화면** → 스크롤 연동(sticky) 구간이라 캡처 시점에 되돌아간다. **수치로 판정하고 캡처는 미확인으로 남긴다**
- **폰 실측은 못 한다** → 크롬 375px 에뮬레이션은 실제 폰이 아니다. 12px 미만 글자를 폰 브라우저가 키워 그리는 현상은 재현되지 않는다. 8px 같은 값은 **실제 폰으로 한 번 봐야 한다**
